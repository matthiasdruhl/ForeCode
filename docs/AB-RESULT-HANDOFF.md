# Genuine A/B results: owner handoff and integration acceptance

Use with the [dated readiness matrix](AB-RESULT-INTEGRATION-READINESS-20261101.md) at its assessed SHA. This checklist receives evidence from the **existing experiment owner**. It authorizes no execution, retry, grader operation, signer, source change or private access. If a required pre-run record was missing at execution, record the limitation; a later document cannot make it prospective.

## Digest and custody crosswalk

Use existing algorithms, not a parallel manifest or signer. `H` is `jsonDigest`/`SHA256(canonicalJson(x))`; envelope and file byte pins are `sha256(bytes)`.

The unchanged five-check baseline IDs are `typecheck`, `build`, `baseline-domain`, `http-integration`, `boundary`. The future suite adds `team-permissions-domain`, `team-permissions-http`, `team-permissions-adversarial` for eight total, as enumerated by `tournamentRequiredChecks` in [`tournament-publication.ts`](../src/lib/experiment/tournament-publication.ts). Supplementary baseline observations use this same eight-check suite in addition to the separate five-check starting-correctness receipt. These group IDs are not individual protected authorization case IDs.

- Full definition: `protocolSubject(definition)`; **operator protocol**: `H(definition.protocol)`. These differ and are not interchangeable.
- **Matched conditions**: [`matchedConditionsDigest(definition)`](../src/lib/experiment/study-identities.ts) hashes conditions, execution conditions, trial policy, runtime, restrictions, tool allowlist, downstream prompt and adapter instructions, preserving array order. Compare both arm conditions after excluding only variant; do not compare only model names.
- Full **task**: `futureTaskDigest(task)` = registered `taskDefinitionSha256` = metric `taskSha256`. `ArmConditions.taskSha256` instead hashes task ID/request/assumptions/acceptance IDs. Preserve that distinction. The existing team task's canonical digest is `fcd6f62dd7ca4c9713c230bd83cc4ede181a9a873c6698d2db2148285ea05883`.
- Bound metric protocol: `H({...initial.measurementPlan, studyId, hypothesisId, contextSha256, taskSha256, matchedConditionsSha256, evaluatorSha256, suiteSha256, policySha256})`. Its lineage `protocolSha256` is not the initial commitment envelope hash or operator protocol hash.
- Scientist chain: `protocol` (null predecessor) → `scientist-commitment` → `scientist-registration` → `scientist-evidence-link`. Each arrow references the predecessor's **exact envelope byte hash**. Initial and binding subjects hash their canonical documents. Registered pair `metricCommitmentSha256` is the initial Scientist commitment envelope hash; `registrationOriginalSha256` is the issued binding envelope hash.
- Metric custody uses existing `telemetry`, not a new `measurement` kind: baseline snapshot subject `H(snapshot)`, predecessor corresponding paired admission; final snapshot subject `H(snapshot)`, predecessor execution envelope; pair subject **raw byte hash** of fixed `metric-observation.json`, predecessor prepared envelope. Pair also binds history and per-arm execution hashes. Keep snapshot/observation/source roots disjoint and immutable.
- Publication pins **three separate identities**: `reportSha256 = H(authenticated private report)`, `projectionSha256 = H(artifact.projection)`, and `disclosureSubject(artifact)`. Also retain exact publication/disclosure envelope byte hashes. Never hash just a title, study ID or receipt ID as a substitute.

For exact private schemas/layouts use [Scientist operator handoff](SCIENTIST-REGISTRATION-OPERATOR-HANDOFF.md), [metric handoff](PROTECTED-METRIC-OPERATOR-HANDOFF.md), [publication handoff](TOURNAMENT-PUBLICATION-HANDOFF.md) and [resolved identities](INTEGRATION-52-55-REPORT.md). Hashing establishes identity; only the existing authenticated custody and protected receipt readers establish the relevant trust.

## Post-run integration sequence

1. **Identify and preserve the existing study.** Obtain its owner-approved package and reader/source identity without touching its checkout or source closure. If a study is active, wait for the owner to release results. A missing result is not permission to launch another experiment. No main merge while its identity matters.
2. **Authenticate privately under separate access authority.** The reporting operator uses the existing archived study/runtime/history/evaluation readers and actual current revocations. Record GO/BLOCKED per package row. Reconcile actual complete attempt inventory with the independent custodian; software cannot discover concealed attempts or establish human independence. Preserve failures and missingness. Never regrade, repair, rewrite or substitute historical originals to satisfy a new reader.
3. **Check comparability before interpretation.** Both starting baselines must be valid; compare entire admitted downstream conditions, frozen task, source/receipt tuples, order and trial policy. A genuinely rejected arm is different from a missing receipt or noncompleted attempt. Retain raw per-arm verdicts even if comparison is invalid.
4. **Assess supplementary metrics separately.** Use `loadPrivateTournamentMetrics` only if its original approvals and live registration requirements were met. B final forbidden edges strictly fewer than A supports that structural prediction; equal (including 0/0) or greater contradicts it. Missing/unsupported imports, incomplete cases, noncompletion, invalid starting authorization or noncomparability prevent an established comparison. Authorization preservation is an independent gate. None changes the deterministic report.
5. **Obtain exact disclosure.** The existing reviewer/custodian approves the sanitized artifact and original report digest. No private comparative numbers, assertions, case diagnostics, source bodies or private paths enter a public PR. Current public projection supports existing effort/check/source identities only. New boundary/case counts or authenticated Scientist lineage require a separately reviewed server-only additive adapter binding the exact projection, authenticated metric original, registration original and A/B run/tree/receipt tuples. This guide neither implements nor authorizes that extension.
6. **Provision privately and freshly load.** The authorized deployment owner supplies the exact typed source-owned configuration to the existing publication singleton. Both `loadApprovedTournamentRecordings()` and `loadApprovedDecisionReports()` use it. The current `null` default remains empty until that separate work is approved. Public serving reauthenticates disclosure/revocations/evaluations each read; it does not reopen all private runtime/history/metric originals or regenerate the private report. The approved artifact commits their prior authenticated interpretation.
7. **Match the display to the exact result.** Existing [`page.tsx`](../src/app/page.tsx) calls `composeReplayPresentation(tournaments,reports)`. Require same study ID and **whole projection digest**, also checked in `DecisionMemo`; same study/definition alone is inadequate. Missing/unavailable/malformed/changed reads withhold the mismatched report. The two reads are fresh but not atomic. Repeat trusted loads for continuing freshness; saved DTOs are not durable approvals.
8. **Review the four destinations using approved data only.** Apply the table below, verify all six result states, and confirm no private fields leak. Separately authorize deployment/publication and preserve withdrawal on expiry/revocation. A supported recommendation remains advisory and scoped to this task; no automatic merge or architecture adoption.

## Result disposition: all six required states

Recommendation rows require comparable conditions, both VERIFIED starting baselines, completed attempts, no blockers/deviations and authentic sufficient final receipts. Individual required-check verdicts remain visible independently. `completed` alone never means VERIFIED.

| Genuine result state    | Tournament / evidence treatment                                                                                                                                                         | Existing deterministic Decision Report                                                                                                                           |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Both verified           | `BOTH_VERIFIED`; correctness tie. Show actual prep-inclusive measurements descriptively.                                                                                                | **INCONCLUSIVE**, “Correctness tie.” Production has no authenticated effort criterion; even lower B cost or supported boundary prediction cannot pick B.         |
| A verified / B rejected | `A_ONLY_VERIFIED`; retain exact differing failed checks and B receipt.                                                                                                                  | **KEEP** for the evaluated task, only with all eligibility gates above.                                                                                          |
| B verified / A rejected | `B_ONLY_VERIFIED`; retain A failure/check/receipt evidence equally.                                                                                                                     | **REFACTOR** as advisory review of B for this task, only with all eligibility gates above.                                                                       |
| Both rejected           | `BOTH_REJECTED`; retain both sets of failures.                                                                                                                                          | **INCONCLUSIVE**; neither satisfied required checks, no winner.                                                                                                  |
| Incomparable            | `NOT_COMPARABLE` or comparability `INSUFFICIENT_EVIDENCE`; retain individual verdicts, differing conditions, history and blockers. Public correctness classification is `INCONCLUSIVE`. | **INCONCLUSIVE** regardless of apparent per-arm advantage.                                                                                                       |
| Missing evidence        | No approved study → empty; failed registered load → unavailable; honestly approved incomplete study → `INSUFFICIENT_EVIDENCE` arm and null receipt where genuinely never issued.        | No mismatched/stale report; an authenticated incomplete projection may yield an **INCONCLUSIVE** report, never KEEP/REFACTOR. A missing outcome is not REJECTED. |

An approved report means authenticated serving scope, not necessarily a supported recommendation. Tests must preserve valid inconclusive reports instead of banning all incomplete publications. One pair is N=1; neither correctness nor supplementary counts establish Meta's incremental benefit or general architecture superiority. That claim needs a separately authorized equally informed control.

Run non-inference tests on reviewed baseline source and disposable synthetic originals only. The existing suites already exercise the following; [fresh validation record](AB-RESULT-INTEGRATION-VALIDATION-20261101.md) distinguishes executed checks from later owner-only acceptance. No new production test switches or authority are needed.

Later, only the actual owner/custodian/deployment operator can verify genuine chronology, independent custody, protected instrumentation, runtime admission and exact disclosure. After they supply an approved package, use the existing read-only `--publication-status` in that private composition and freshly load both catalogs at actual time; inspect exact tuples and matching digest privately. No grader or experimental workload is necessary for publication acceptance. Fresh browser checks of an approved populated deployment require its separate disclosure/deployment authority; synthetic/browser success cannot stand in for those facts.

Optional interpretation additionally requires `ScientistEvidenceLinkOriginalSchema` from [`createScientistEvidenceLinkReader`](../src/server/meta/evidence-link-reader.ts), exact preparation conformance and publication/run/tree/receipt binding, current registration/link, and explicit `meta-scientist-allowlisted-summary.v2` disclosure to named eligible models plus consent/budget authority. Its usable time ends no later than the earliest parent proposal TTL, issuance TTL, registration/link or required-original expiry; context change/revocation/process replacement can end it earlier. If expired, omit interpretation and keep the deterministic approved result; never reissue onto old preparation or extend the 30-minute window.
