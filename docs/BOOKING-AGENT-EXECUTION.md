## Trusted boundary

The agent no longer executes in the outer sbx guest namespace. That namespace contains a root-owned Python supervisor, a per-run budget broker and the nested Docker daemon. Only those trusted components control lifecycle and export. The coding agent runs as UID1000 in a separate network-none worker: read-only root/fixture, only `src/` writable, capability drop ALL, no-new-privileges, CPU1, memory/swap768MiB, PIDs128, finite tmpfs and no Docker/host/SSH/credential socket. Docker inspect readback must match the policy. Dependencies, evaluator, task record, supervisor and original evidence are outside its writable/reachable scope. The immutable worker image must be independently reviewed and credential-free. Codex state uses a separate16MiB UID1000-owned tmpfs at `/home/agent/.codex`; its reviewed `config.toml` remains a read-only file bind. This prevents Docker’s root-owned mount-parent creation from blocking app-server startup.

Codex runs with `--sandbox danger-full-access` strictly inside this confined worker, following the [documented container setup](https://learn.chatgpt.com/docs/agent-approvals-security). Docker supplies the enforced boundary: its existing cap/seccomp settings prevent the nested namespace that Codex’s inner sandbox needs. No host/container privilege, mount, network or capability is added for Codex tool execution. The reviewed worker and budget broker enforce the limits even if a shell invokes tools directly. The trusted task also supplies `tokenLimit` to a finite native Codex rollout-budget table with unit sampling/prefill weights, preventing an unrelated inherited experimental cap from stopping the session. The native guard remains enabled; the outside broker separately reserves tokens and microUSD before requests.

The supervisor lives outside that worker's PID namespace. Its durable run UUID/nonce, boot ID, request digest, container ID, process birth identity and heartbeat bind the attempt. It removes the **entire worker**, including detached/reparented/group-escaped processes, before capturing source. The worker has restart=no and removal is rechecked. It then copies into a root-only sealed tree, compares original/second captures, freezes permissions, checks absence again and returns bounded bytes directly to the host. It never stops an untrusted VM and then runs an export command inside it. The trusted outer VM can remain running during transfer; the removed untrusted container cannot be restarted by its old ID.

A host/controller interruption leaves the independent watchdog running; missing heartbeat for15 seconds or the wall deadline removes the worker. Loss of the supervisor, changed VM identity/boot, uncertain termination, failed export, cancellation or cleanup refusal forbids sealing/grading/publication. A forcibly killed trusted supervisor is detected, rather than represented as confirmed termination; owner cleanup is required. The worker cannot signal that root supervisor through its separate PID namespace. Compromise of the outer trusted VM, kernel/Docker escape and malicious operator activity remain outside this process-boundary proof and require independent review.

The TypeScript adapter checks current lease, exact review/revocation binding and VM identity at each stage, plus full installed inventory immediately before launch and grading. Only an in-process marked finalization returned by the concrete adapter after these checks authenticates its controller handoff. Parsed JSON, cloned flags or `terminationConfirmed:true` supplied by an arbitrary adapter do not authenticate it.

## Provider and spending envelope

The worker receives no provider credential or external network. Its local Node HTTP bridge forwards only Responses POSTs to a per-run Unix socket. The trusted broker alone reaches the selected fixed Responses endpoint through the host-managed Docker credential-injection proxy. The only supported pairs are `muse-spark-1.3` with Meta and the historical `gpt-5.6-sol` with OpenAI. Their respective proxy sentinels are `forecode-meta-sandbox` and `sk-sandbox`, never copied keys. Configuration, proposal, review, supervisor task and response validation bind the selected model; no automatic fallback exists. There is no redirect, arbitrary endpoint/model, hosted tool, media or previous-response/conversation lookup. Codex delivery/cache metadata is stripped; ordinary billed context remains explicit text. Encrypted reasoning replay is accepted only for exact items received by this same broker after a reserved upstream request; each occurrence reserves that previous entire maximum output allowance again as input. Only hashes/bounds and validated usage/status are retained in the private budget record. Meta may encrypt the same reasoning item differently in `response.output_item.done` and the terminal response. Both exact received ciphertexts are bound only after valid terminal usage and matching output index, item ID and all non-cipher fields; foreign, changed or duplicate items fail closed. Arbitrary copied/changed opaque history is denied. Unknown request fields fail closed; automatic compaction is set above the largest1M-token reservation ceiling (Meta up to1M, historical OpenAI100k). A provider/Codex combination requiring unsupported remote history is unavailable, not silently substituted.

Before each single upstream attempt, the serial broker durably reserves conservative input bytes plus framing allowance and maximum output tokens, at independently approved integer microUSD tariff ceilings. It injects `max_output_tokens`, the exact provider-profile tier and store=false. Failed calls keep their reservations; restart never resets an attempt's budget and neither transport performs a hidden paid retry. A transport failure or unverified provider response durably blocks all further upstream requests in that attempt. Before returning a response, the broker requires the exact model and profile tier, one terminal completed/incomplete response (including for streams), and internally consistent nonnegative integer usage within the reserved input/output bounds. Missing usage, tier/model drift, truncated or duplicate terminal events and excess usage fail closed. Full reservations remain charged internally even for a verified incomplete response; no refund or measured-bill claim is inferred. The circuit breaker prevents subsequent calls; it cannot retroactively undo a provider charge that already exceeded the assumed envelope. The independent watchdog remains separate from slow provider I/O. Actual tokens/cost remain null without trustworthy telemetry; reservation totals are not measured usage.

This mechanism requires independent verification of the exact tokenizer/framing/tariff ceilings, API support for the output cap, credential-injection path and any account hard cap required by the spending decision. It does not prove an unknown vendor tariff or grant spending authority. Current observed agent auth was OAuth; that does **not** establish compatible API account access, current `gpt-5.6-sol` availability or billing enforcement. No price/model fallback is implemented. All example pins remain placeholders, and example rates are proposed ceilings rather than spending approval. The disabled example uses 5 input and 20 output microUSD/token: these cover the October 28, 2026 documented standard text prices of $4 input/$20 output per million tokens and the 1.25x cache-write rate ($5 per million input tokens).
