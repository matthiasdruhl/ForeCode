Limits here are pinned proposals, not runtime enforcement. There are exactly A and B, sequential predeclared trials, no undeclared retries and no comparative winner while gates are blocked.

Two commitments have different chronology:

1. **Before architecture selection/preparation:** `futureProtocolCommitment(draft)` pins the exact task, oracle descriptor, original source/lock/roadmap, scenario/intent, conditions, execution identities/resources, predeclared run IDs/order/retry policy and study ID. It deliberately excludes prepared B source and observed preparation costs, which do not yet exist. The independent custodian must hold and authenticate this record; the software never asserts that a hash/timestamp proves that happened.
2. **After preparation, before downstream outcomes:** freeze the completed draft/pair, including actual prepared tree/commit, preparation-record pin and metrics, with `jsonDigest(validateFutureStudy(draft))`. `requireFutureStudyCommitments` compares both against independently supplied original pins. A changed prepared tree changes the completed-draft commitment; changing task/evaluator/protocol changes both. Proposed timestamps must order protocol freeze < selection < pair freeze; B preparation must begin after selection and finish before pair freeze. Existing reporting rejects downstream attempts before pair freeze and preserves extra/failed/cancelled attempts.

The operator completes a `booking-preparation.local.v1` B record: study/task/protocol, original and prepared commit/tree/lock, preparation prompt hash, review/execution record hashes, start/end and metrics. `loadPreparationRecord` requires independently supplied byte hash, canonical operator-owned private directory, bounded non-symlink/non-hardlinked regular file and disjointness from both repositories and all supplied agent workspaces. It returns an immutable process-marked record; parsed JSON/serialized copies have no such authenticity. The operator must supply a complete inventory of task/agent roots; this filesystem check is not containment proof. Reload original bytes immediately before assessment.

`assessFutureStudy` checks record/source/task/protocol/cost linkage, preparation chronology and that B baseline grading starts after preparation finishes. The existing report requires authentic A/B baseline verification of prepared sources before future work; a failed baseline makes the study NOT_COMPARABLE, while missing/forged evidence stays insufficient. Record/review hashes authenticate neither the referenced approval nor execution/metrics; the report explicitly retains that blocker. B preparation costs remain separate, and preparation-inclusive totals reuse null-preserving accounting. Unknown is never converted to zero. No free preparation phase or implicit cost estimate is introduced.
