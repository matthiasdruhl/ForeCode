## What the admitted command does

The controller first runs the eight lifecycle cases, with no candidate source. Each case uses a distinct host-generated UUID, the pinned image and the same worker policy as booking grading. Fixed worker/driver programs are the only executable inputs. The request digest binds all run IDs, implementation and image. The host derives acceptance from actual protected transport/driver observations and rejects incomplete case sets, wrong identities, false timeout/signal/output claims, missing or stationary heartbeats, source mutation and unconfirmed recovery. A JSON success label alone cannot satisfy these checks.

| Fixed case          | Required observed behavior                                                                                                                                                                  |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Normal exit         | Worker exits 0 through the protected driver.                                                                                                                                                |
| Worker failure      | Worker exits 7; nonzero exit remains recorded.                                                                                                                                              |
| Timeout             | A worker is observed alive; the protected driver ignores TERM and the deadline escalates to KILL before independent recovery.                                                               |
| SIGINT / SIGTERM    | The exact signal reaches the protected driver; its bounded worker command is cancelled.                                                                                                     |
| Output limit        | The fixed flood reaches the 4096-byte worker-output cap.                                                                                                                                    |
| Detached descendant | A harmless detached process advances a heartbeat and cannot write the read-only export; the driver is killed with SIGKILL and run-scoped recovery removes the worker.                       |
| Cleanup refusal     | A fixed fault refuses removal before modifying the owned worker; it remains observable, then real recovery must succeed. This is controlled fault injection, not a measured Docker failure. |

All prior run controllers/workers must be absent before each following case. Harmless workers self-expire after 30 seconds if left running; the guest suite has a 90-second deadline, host transport 95 seconds, and host recovery an independent 60-second budget. No guest shell or caller-selected command is used. Read-only export marker bytes must remain identical before/after every case. The controller requires exact worker **and controller** absence after stop/restart: recovery of a revived controller is recorded as a failure rather than silently counted as successful absence.

Full acceptance then freezes only the reviewed fixture as data and creates four source envelopes: baseline, distinct final (identity marker), deliberately broken ownership guard, and that regression plus candidate-claimed PASS stdout. It asserts that only baseline equals the baseline tree. No variant is imported, installed, built or executed on the host. Each goes to the protected guest with exact run/tree/evaluator/suite/policy identities; the guest independently decodes and hashes source before running tools.

Each tool/oracle uses a new labelled worker with network none, read-only root/source/bridge, unprivileged UID, no capabilities/escalation, one CPU, 768 MB with no extra swap, 64 PIDs, 256 descriptors, 256 MB work/32 MB temp/16 MB shared-memory tmpfs, and no restart policy. Private work copies are writable for Next/TypeScript; the source mount stays read-only. Native tool resolution uses only the pinned image and dependencies; candidate package scripts are not invoked. RPC startup/replies and output/deadlines are bounded. The independent public domain/HTTP assertions remain outside the worker. Candidate stdout and RPC values are not verdict authority.

The boundary check combines the existing static scan with a fixed worker denial probe for evaluator files, source mutation, synthetic credential locations/environment, Docker/SSH sockets, external/metadata/host-service network attempts. These finite worker probes do not establish complete VM/host isolation; the latter is an admission prerequisite. The guest reports only protected observed exits. Baseline and distinct final must load as scoped VERIFIED; the regression and claimed-success variant must load REJECTED. Missing checks stay `not_run` and normalize to INSUFFICIENT_EVIDENCE; they cannot complete acceptance.

A trusted controller records PID plus Linux birth identity. Recovery terminates that exact controller, removes only exact run-labelled nested workers, checks absence, stops/restarts the grader, checks no worker was removed after restart, and confirms stopped state. No run can publish until cleanup and host candidate/implementation freshness checks pass. Interruption or cleanup failure retains the shared lease for owner recovery; the runner never deletes a VM or stops the agent VM. It cannot prove safe future guest-sudo agent supervision, so that path remains unavailable.

Private output: `protectedRoot/ACCEPTANCE_UUID/{acceptance.json,lifecycle-observed.txt,lifecycle-stderr.txt}`; per-scenario `protectedRoot/RUN_UUID/{candidate/,grader-observed.txt,checks/,evaluation.json,allowlist-entry.json}`. Failed attempts retain observations, exit reasons, timing/output hashes and recovery state. Runtime pins include implementation, image, tooling and limits; configuration/review digests are included in each check artifact. The controller exercises existing publication → protected loading → verdict normalization and never registers entries in hosted server configuration. Do not publish candidate snapshots or raw diagnostics. Probe-only mode records `mode=lifecycle-only`, `inference=NOT_RUN`, `realAgentExecution=NOT_RUN`, and an empty evaluator-entry list.
