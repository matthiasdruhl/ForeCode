### Private completion-contract observations

The trusted team broker retains append-only `request-NNNN-{stage}.json` observations beside its private `budget.json`, outside worker mounts. Stages are admitted, upstream-started/upstream-failed, response-received and response-accepted/response-rejected. Admission hashes and projects the final normalized bytes actually returned by reservation, including selected output allowance. Metadata contains only fixed phases, limits, tool names from the existing allowlist, bounded item-type counts, instruction digests/lengths and time observations. Raw instructions, source, history, arguments, credentials, provider IDs and usage are excluded from these diagnostic files.

Each observation is bounded to8192bytes, synced through a private temporary file, then atomically published under an exclusive immutable0400 name and directory-synced. A leftover `.next` file is not an observation. An existing/aliased file, invalid event order or storage failure fails closed before delivery or any further request; reservations are never refunded. Rejected response bytes remain in the existing private failure store where storage permits. A later diagnostic failure does not erase already validated usage. Unknown usage remains unknown. A failure to retain budget, rejected bytes or rejection diagnostics does not replace the original rejection cause.

An admitted record proves durable reservation, not that a provider request was sent. Broker elapsed times use one process-local monotonic clock. Upstream-started records callback entry, not provider arrival; response-received records bytes reaching validation, not inference-only duration. Missing/partial stages remain missing/partial after interruption. Provider echo shapes are explicitly untrusted observations and establish no correctness, invoice or acceptance. These additive guest records survive normal cleanup beside budgets and are retained/exported through the existing owner-private operational evidence procedure; they do not alter historical original/report schemas or grant authority.

Response shape is stored once at response-received with `observationOnly:true`; terminal output, added and done counts are separate. Only response-accepted has `responseValidated:true`. A complete accepted record means broker validation passed, even if a subsequent directory-sync or client delivery failed; it is not a delivery receipt. There is no second mutable completion-contract store.

Full20-round scripted-native controls exercise public cookie and boundary rejection, repair, growing tool history and final response. Valid final text and JSON/SSE message-plus-tool refusals are separate controls. Correct refusal can coexist with sealed public READY and native failure. No scripted control proves that a real model follows the same instructions.
