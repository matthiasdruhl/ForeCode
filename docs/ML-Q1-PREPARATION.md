## Data and evaluation

Use text-only, human-reviewed architectural demonstrations with explicit source/license/rights/sanitization identities. Separate repositories, task templates and reviewed near-duplicate groups across train/validation/test BEFORE hyperparameter selection. The validator catches exact/normalized repeated prompts, selected secret/PII patterns and malformed/unsupported strategy answers. It is a supplement to independent data review, not a privacy certification. Synthetic test examples remain SYNTHETIC_TEST_ONLY. A demonstration is not a verified outcome. A verified-success label additionally requires an AUTHENTIC admitted comparable observation with an independently passing selected strategy; self-attested hashes or synthetic receipts are insufficient.

Privately prepare messages with fixed reasoning strength and the pinned processor. Hash the actual rendered chat template and tokenized datasets; verify assistant loss masks, end-of-turn tokens, truncation and ABSTAIN cases against the real processor before training. Then perform only a separately approved two-optimizer-step smoke, save, reload into a fresh original base and compare adapter tensor identities/generations. Record peak memory after optimizer initialization and saving. No full run before that reload succeeds.

Use a frozen untuned-base versus adapter comparison on the SAME original revision, prompts, decoding, eligible strategies and independent held-out families. Measure output validity/eligibility, falsifiability, abstention, risky unnecessary changes, latency, tokens and cost; independent blind human rubric review may describe reasoning quality. Architectural correctness requires separate authenticated tournament outcomes. SFT validation loss or better formatting establishes no architecture or RL benefit. QLoRA is supervised adapter tuning; the small LinUCB selector is a separate learning mechanism. GRPO is outside this workstream.

## Compute and cost gate

Reference hardware is one H100 with enough VRAM and private checkpoint/dataset disk. Capacity, storage, checkpoint reload and deterministic behavior must be preflighted; a seed alone does not guarantee bitwise GPU determinism. Actual ForeCode VRAM, runtime and disk usage are unknown. No GPU provider quote has been obtained.

The draft approves USD 0 and GPU hours 0. estimateTrainingCost performs arithmetic from an explicitly supplied quote: GPU rate × hours + storage + egress + inference. Unknown inputs remain unknown in the draft. Its unit test's USD 3/hour × 2 hours plus USD 4 overhead = USD 10 is fictional arithmetic, not a quote, recommendation, or permission. Obtain actual dated rates, quotas, maximum hours/retries, cancellation behavior and an absolute all-in spending cap before any resource creation. Account for failed runs and separately budget held-out grading and serving.

Inference serving is separate: local Glimmer base + exact adapter + original tokenizer with reviewed quantization and bounded latency/memory. No Spark API fine-tune or adapter-hosting ability is assumed. Serving must pin an approved runtime, verify reload and base/adapter selection, preserve consent/provenance and avoid external uploads.
