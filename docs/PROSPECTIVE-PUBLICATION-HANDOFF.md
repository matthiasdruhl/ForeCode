## Source-owned configuration and immutable layout

The optional `ApprovedTournamentConfig.prospectiveEvidence` contains:

- `custody`: the existing `ScientistCustodyConfig` shape, with a fixed private original root, the **same** reviewed base disclosure key, key digest, current revocation-state digest and workspace inventory; exact record/document filenames and byte hashes in its allowlist.
- `entries`: a fixed `Map<studyId, {disclosureId}>`; every ID must belong to the already registered base studies. Each disclosure ID occurs once; no extra custody entries or fallback authority is permitted.

Use an owner-controlled 0700 directory outside repository/workers, with immutable single-link 0400 files `revocations.json`, `<id>-record.json` (the actual signed envelope bytes) and `<id>-document.json` (the strict sanitized document). The generic original reader accepts only fixed flat allowlisted filenames. Never deploy a private key, protected assertions or a broad original directory. The revocation bytes/digest must equal the reviewed current base publication state. Preserve original evidence and hashes; packaging copies are not new independent custody.

The read-only factory lives in `evaluation-store.ts`, the repository's sole reviewed filesystem exception. It reuses the existing signature, path, ownership, alias, hash and revocation checks, then enforces disclosure kind, current expiry, subject, study and prepared predecessor. `loadProspectivePublications` first authenticates the current base publication **and its protected receipt joins**, then rereads the exact base artifact to obtain its private-report digest (absent from v1 public projection). Every identity must match. Missing, revoked, expired, tampered or mismatched evidence yields no supplement; no cached result or request/env-selected root/key is used.

The same production singleton exposes `loadProspectiveEvidence()`. Existing `inspect()`/`--publication-status` covers the unchanged base catalogs only; provisioning the addon also requires its expected study in `loadProspectiveEvidence()` with state available and zero unavailable entries. The page loads it alongside the two unchanged base catalogs. Presentation rejoins exact projection/prepared identities before passing public-safe data to the existing hypothesis evidence view and measurement rail. Without an eligible supplement, the existing metadata-only lineage limitation and Unknown measurements remain. No new decision authority, execution route or model request is added.
