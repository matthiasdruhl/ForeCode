The static collector supports relative imports, `@/` rooted at `src/`, `.js` references to TypeScript sources, and unique `.ts`, `.tsx` or index resolution. It ignores only external packages explicitly frozen in `externalPackages`; subpaths use the frozen package root. It does not execute tsconfig plugins or custom loaders. Freeze the actual source inventory, parser/toolchain, rules, external package list and alias semantics under the evaluator/suite/policy identities. The protected collector must attest inventory completeness and bind each snapshot to its exact tree manifest. The pure helper cannot establish completeness from a caller-supplied map.

This metric measures the specified direct static dependencies, not all coupling, complexity, runtime capability flow, transitive dependencies or authorization quality. Unsupported language/toolchain features require abstention and a separately reviewed new protocol, rather than silently broadening resolution. Do not infer counts from the existing single `boundary` check's pass/fail result.

## Window, prediction and independence

Take exactly two retained snapshots per arm: the admitted prepared baseline immediately before the downstream agent starts, and the sealed final tree at that arm's single terminal attempt, before any repair or feedback-driven retry. Run both collectors and the identical frozen acceptance suite at both snapshots. Partial trees, missing snapshots and runs that fail to complete remain descriptive observations and cause comparative abstention. No “best checkpoint” selection. Preparation attempts remain separately recorded; this metric does not estimate transient violations introduced and later removed during coding.

The new strict prediction is **B has fewer final forbidden edges than A**. Support requires complete comparable measurements and B's final count strictly lower. Equal counts, including zero/zero, or a higher B count contradict this strict prediction. Report both baseline counts and final counts; do not quietly switch to improvement-from-baseline after seeing results. Unknown measurements or invalid starting authorization cause `not_established`. Behavioral failures are reported separately: fewer edges can coexist with an authorization failure and cannot justify a recommendation. Both baseline and final authorization must be preserved for the authorization gate. Both architectures passing the independent suite is a correctness tie, not architectural superiority.

The observation unit is one registered pair on one frozen task, **N=1**. Imports, lines, assertions, HTTP calls, snapshots and A/B runs are correlated within that pair, not independent samples. Duplicate seeds or rerunning the same task do not establish generalization. A future repeated study requires predeclared genuinely independent task/repository families and analysis; this small protocol offers no statistical significance or broad superiority claim. A/B does not isolate Meta's contribution; that requires an equally informed strong non-Meta control under the same conditions, with Meta preparation costs included.
