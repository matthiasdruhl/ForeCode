## Source completeness and observation window

`collectSealedMetricSnapshot` consumes a directory, an expected complete sealed manifest and tree digest. These arguments alone confer no authority. The authenticated reader obtains their expected values from `PreparedStudy` and `AuthenticatedArm` originals, checks the prepared tree against the plan, and requires independently held observation originals. A caller-supplied source map cannot establish completeness.

The collector enumerates **every entry**, including non-source files, with no generated/hidden-file exclusions. Files must exactly match the sorted, duplicate-free full source manifest. Unknown files/directories, omissions, hash mismatches, writable source files/directories, symlinks, hardlinks, unsafe paths and aliases fail. Directories/files are operator-owned; all source files and directories must be sealed without write bits. The read uses the existing bounded `protectedRead` no-follow, regular-file, inode/metadata/size checks. A second full scan catches mutation around parsing. The adapter also rejects overlaps between its original root, all retained source roots, repository/planning roots and complete worker workspace inventory.

The original existing transfer/manifest ceiling (100 files), 2 MiB per transfer file and 8,000,000 total bytes remain. Measured source remains bounded to 1,000 files, 256 KiB/file and 4 MiB total, within that transfer ceiling; traversal is bounded separately. Original JSON uses the existing 1 MiB protected-read ceiling. Larger complete observations abstain/refuse loading rather than increasing limits. Unsupported source paths/assets are retained in the full manifest and make coverage unknown, never silently omitted. Strict UTF-8 decoding rejects malformed source. Next `[id]`, `[...slug]` and `[[...slug]]` paths are supported.

The reviewed controller must collect the prepared baseline at a release barrier immediately before downstream launch, hold its signed snapshot record before that launch, and retain that sealed tree. The run original's initial manifest must be exactly that baseline. Snapshot collection/custody follows prepared and runtime admission. No intervening source mutation is permitted. At the one terminal attempt, stop/finalize the worker and collect its sealed exported final tree before any repair/retry; bind its manifest to the terminal run and execution original. Retain failed, cancelled, timed-out and denied attempts. The loader additionally enforces the existing `teamTaskSha256` constant; another task needs separately reviewed integration. The loader does not pick checkpoints or execute a worker. Custodian-approved chronology and a real release barrier remain instrumentation obligations; local clocks and filesystem hashing alone cannot prove historical timing.

## Static and authorization measurements

Boundary violations remain distinct forbidden **resolved direct static source dependency pairs**, under the identical protocol rules for both arms and both snapshots. Imports, reexports, import types and type-only imports count equally. Relative resolution, `@/` at `src/`, `.js` references to TS, unique modules/indices and predeclared external package roots retain PR49 semantics. Duplicate declarations still count one pair. Deterministic ordering prevents filesystem enumeration order from changing the original.

Only present, exactly declared side-effect stylesheet imports are exempted; stylesheet bytes remain in the sealed tree. Value imports/reexports, undeclared stylesheets, other assets/loaders, import attributes, CommonJS loader references, dynamic imports, unresolved/ambiguous resolution, parse/reference errors and missing rule endpoints make coverage unknown. More than 10,000 observed dependency declarations returns incomplete coverage with bounded empty edge data, never a usable zero count. This is a conservative static syntax metric, not exhaustive runtime capability, alias, transitive dependency or complexity analysis. Unsupported forms require a separately reviewed protocol, not result-driven extensions.

`ProtectedAuthorizationObservationSchema` contains only exact evaluation identity, receipt digest and bounded `{caseId,outcome}` observations. Case IDs and their exact expected semantics must be frozen by the independently reviewed suite/metric protocol before either arm. Each ID is one acceptance case, regardless of assertions/HTTP calls/retries. No hidden assertion text, inputs, candidate code execution, or arbitrary executable selector is introduced.

Per-case outcomes require their own independently held snapshot original **and** a matching `TrustedEvaluation` from the existing protected store. The old group-level checks cannot be converted into case counts. Duplicate/unexpected case IDs and inconsistent receipt identities are rejected. Missing cases or invalid/not-run outcomes cause unknown authorization counts. Missing/error required group observations invalidate purported per-case passes. A case failure beneath an all-pass protected receipt is rejected. Failure of another check may coexist with all authorization cases passing; the existing receipt/verdict engine remains authoritative.

The separate metric baseline must use the same future evaluator/suite/policy and eight required checks as the final observation. Its single per-arm evaluation run ID is deterministically `metric-baseline-${downstreamRunId}`; the fixed operator configuration must match this value, preventing post-outcome selection among baseline evaluation IDs. It supplements the existing unchanged five-check baseline, which cannot establish starting team-authorization behavior. Final metric receipt run ID equals the downstream terminal run ID. Both receipt identities pin the exact source and original fixture. Baseline receipts finish before downstream start; final receipt execution follows downstream start; all observations finish before their custody records are held.

## Fairness and interpretation

The existing authenticated measured report gates comparability, complete attempt history, declared order/conditions, runtime deviations, failed attempts, source custody and cleanup. Its comparability must be `COMPARABLE` before this adapter establishes the strict metric prediction. The supplementary result cannot override a report verdict or authorize a run.

The prediction uses absolute **final** counts: B lower supports; equal (including zero/zero) or B higher contradicts; incomplete/missing/noncomparable data or failing starting authorization does not establish it. Baseline and final counts are retained. Fewer edges can coexist with authorization failure; architecture never proves correctness. Two passing authorization results are a correctness tie. `engineeringRecommendation` still defers to the authenticated deterministic report.

Existing preparation-inclusive metrics and all preparation attempts are carried through unchanged. Unknown time/tokens/cost stay null; reservations are not charges. Per-phase file-touch counts are never summed as distinct files. The observation unit remains one independent registered pair, N=1 when eligible, with no significance or generalization claim. Synthetic origin is retained even after successful authentication of test-owned bytes.
