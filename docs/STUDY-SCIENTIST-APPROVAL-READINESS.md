No placeholder hash, fabricated consent event or newly created trust root substitutes for these prerequisites.

## Lifecycle and remaining timing decision

The service's 1,800,000 ms TTL and parent-proposal/process-local semantics are unchanged. The controller adds a conservative deadline starting at proposal **start**, earlier than the service's accepted-parent deadline, and narrows it to the initial originals' earliest expiry. Abort signals bound approval/custody waits and dependent calls. Current issuance and original expiry are checked again after asynchronous resolution. Expired or aborted work cannot enroll or gain another lifetime.

At 600 seconds per arm, maximum sequential coding time is 1,200,000 ms. All other planned work plus safety margin must total **less than 600,000 ms**. The operator refuses an estimate at or above the fixed full TTL or beyond the initial originals' remaining interval. Status labels a passing estimate `UNVERIFIED_ESTIMATE`; arithmetic cannot establish actual preparation, protected grading, human/custodian response or runtime timing. The operator also cannot extend freshness after it returns registration; the full measurement path must remain within the existing live resolver window.

Before genuine generation, an operator must establish a credible complete timetable for preparation, protected baselines, admissions, both maximum coding windows, finalization, metrics and any requested interpretation. The harmless local rehearsal below demonstrates the software handoff and actual transport spacing only. It does not establish that this genuine end-to-end schedule is feasible. If it is not feasible, retain the blocked state; no TTL change or durable issuance design is included.
