# Authenticated tournament publication: audit and operator handoff

This change implements a read-only production adapter and safe inspection. **No real study is provisioned or approved for public disclosure by this PR.** Case 13 and other historical observations remain private. Synthetic signatures and passing tests establish software behavior only. No new experiment, inference, protected grading, private-original access, disclosure issuance, production activation or deployment is authorized here.

The missing integration was the shared production registration adapter, exact registration validation, and safe inspection. The existing stores already provided custody, signatures, byte/source/receipt checks, revocation, bounded reads and revalidation. This PR adds no filesystem capability, runner, evaluator, signature system, decision algorithm, frontend, public API or mutable registration endpoint.

The server does **not** regenerate the private measured report or reopen runtime/history/telemetry originals on each public read. Their authenticated interpretation is committed by the exact approved disclosure artifact and its pinned bytes; the original private report remains private. Current publication/disclosure/revocation and protected evaluation bytes are reauthenticated on every read. A signed projection is not public independent observability of private assertions. Retain the archived original reader and source identity for historical reports; do not recompute old receipts with new implementation hashes or rerun a grader to make them fit.

The full projection digest pins task ID/hash, study definition and protocol/prepared commitments, model/order/comparability, original/prepared/final architecture identities, receipt IDs, metrics, attempts and approved metadata. File-byte pins separately bind the publication, report digest and disclosure envelope. Hashes do not create approval; the existing independently authenticated disclosure and original receipts remain mandatory.

Publication layout uses the existing fixed names:

```text
publication root / <registered-directory> / tournament-publication.json
independent authority root / <disclosure-id> / disclosure-original.json
independent authority root / revocations.json
protected evaluation root / <registered-directory> / evaluation.json
protected evaluation root / <registered-directory> / <original check evidence paths>
```

Publication/authority directories must be canonical, operator-owned and private (0700); publication, original envelope and revocation files must be immutable/read-only (0400), regular, owner-held, single-link files without symlink aliases. Reuse the existing protected evaluation store's custody setup unchanged. Retain exact original bytes, not regenerated signature envelopes. Mount these read-only in the eventual authorized server runtime; never serve the directories as assets or include them in a public image/repository.

## Remaining operator-only steps

1. Obtain separate authority to access the selected genuine private report and originals. Using its archived trusted reader, freshly authenticate the actual protocol, prepared sources, baselines, downstream outcomes, complete attempt history and unknown-aware accounting. This PR grants none of that access or execution authority.
2. Have the designated reviewer approve the exact public metadata, source-path/hash subset, metrics, history, limitations, original private-report digest and disclosure scope/interval. Obtain the genuine held disclosure through the **existing** custody mechanism; do not create a replacement authority or backdate approval.
3. Under separate provisioning authority, place only the exact approved publication and original disclosure/revocation bytes at the private fixed layout above. Independently review all original evaluation identities/byte pins, key pin, directory custody and workspace inventory. Do not broaden the original scope or copy protected content into public Git.
4. In a separately reviewed **private deployment source composition**, replace the sole `createTournamentPublicationReader(null)` argument in `src/server/artifacts/approved-tournament-publication.ts` with the typed exact `ApprovedTournamentConfig` assembled from those approved values. Both production loaders already use that singleton. Do not add an environment/path/key/request selector, runtime setter, or second registration list. Keep all private composition values and paths out of this public repository. This controlled source composition is the remaining activation boundary, not a missing automatic enrollment service.
5. Run the read-only `--publication-status` command below inside that approved deployment composition. Check both catalogs through their existing server functions at the actual current time. Inspect the exact resulting report and its scoped limitations privately; availability is not an assertion of a decisive winner. No inference, runner or grader is needed. Resolve failures by reviewing original custody/approval; never edit evidence or weaken guards.
6. Obtain separate deployment/publication authorization for the exact reviewed build and approved study scope. Deploy only then. Retain revocation monitoring and a means to withdraw the composition. Changed revocation bytes, expiry, removed files or changed evidence cause fresh reads to withhold studies; no cached authenticated result is retained.

## Safe read-only inspection

Extend the existing operator CLI; no second CLI or web inspection route:

```sh
node --conditions=react-server --import tsx scripts/experiments/tournament/cli.ts --publication-status
```

The command accepts **no** study, path, key, input JSON or timestamp argument. Exit 0 means all configured publication registrations loaded, 2 means unprovisioned/empty, and 1 means unavailable or partially unavailable. It emits only `state`, available/unavailable counts and at most 20 validation-stage failures (or one global configuration/store failure), with zero-based registration indices. Map indices to the privately reviewed registration list. It prints no projection, study metadata, paths, check content, transcripts, keys, caught exception text or stacks.

| Bounded reason code                                            | Review action                                                                                                                                                                                |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CONFIGURATION_INVALID`                                        | Review exact source registration membership, uniqueness, required projection pin and evaluation references.                                                                                  |
| `STORE_UNAVAILABLE`                                            | Review existing store roots, permissions, workspace separation, key configuration and custody setup privately.                                                                               |
| `DISCLOSURE_UNAVAILABLE`                                       | Review exact publication/envelope/revocation bytes, signature, study/predecessor binding and current disclosure interval. This deliberately does not distinguish sensitive low-level errors. |
| `APPROVED_PROJECTION_MISMATCH`                                 | Review projection digest and exact A/B pairing against the approved source registration.                                                                                                     |
| `BASELINE_EVIDENCE_UNAVAILABLE` / `BASELINE_IDENTITY_MISMATCH` | Review original baseline bytes/check artifacts and original source/evaluator/suite/policy/receipt identities.                                                                                |
| `FUTURE_EVIDENCE_UNAVAILABLE` / `FUTURE_IDENTITY_MISMATCH`     | Review original final bytes/check artifacts, exact run/final source/evaluator/policy/receipt identities, or the explicit never-issued final registration.                                    |
| `CHECK_PROJECTION_MISMATCH`                                    | Review all eight required public check IDs/statuses against the original protected checks.                                                                                                   |

Inspection reports authenticated **publication availability**, not Decision Report decisiveness. The unchanged analysis engine may still abstain (or withhold an internally inconsistent analysis). Call `loadApprovedDecisionReports()` in the approved server composition for the actual report catalog. Do not expose a private report to diagnose the public catalog.

## Decision and measurement limits

KEEP requires comparable completed arms, valid starting baselines, A verified and B authentically rejected. REFACTOR requires the reverse. Missing/insufficient evidence, noncomparable conditions, blocked/failed/canceled execution, blockers or deviations remain inconclusive. Both verified is a correctness tie; both rejected establishes no winner. Pure offline criterion assumptions cannot enter the production composer, even with complete telemetry. Unknown preparation or downstream measurements remain null, not zero; reservations are not invoices, modeled effort is not measurement, and phase file counts are not added. All claims remain limited to the one exact study, task, source trees and required checks, with no Meta incremental-benefit claim.

Tests use disposable test-owned custody, generated synthetic keys and inert observations only. They cover fresh serving and report composition, all four correctness outcomes, missing/incomplete evidence, mismatched identities/conditions, history/unknown measurements, unsupported effort assumptions, registration failures, tamper/expiry/revocation and protected-content exclusion. They do not establish real publication authorization, independently observable historical results, operational mounting or deployment. Those remain the operator handoff above.
