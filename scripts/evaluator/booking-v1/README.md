# Trusted booking evaluator building blocks

This directory stays outside every agent task export. `oracle.ts` defines 13 baseline domain cases; `http-oracle.ts` defines five baseline HTTP cases. Both accept injected subject factories and import no implementation or visible tests from the booking package. Their expectations are public baseline requirements, not secret held-out future requirements.

Current unit tests pass the newly authored, reviewed baseline to those factories. They also deliberately break an owner check and confirm the oracle rejects it. These are developer tests, not a sandbox experiment. Never load agent-modified subjects on the host: the local controller must supply factories **inside the separately verified, network-off grader guest**, using a reviewed bridge and pinned tooling. Server-only modules require the proper server runtime condition there; the local Vitest shim is only a developer-test convenience.

`snapshot.ts` hashes bounded regular-file manifests, excludes root-level Git/dependency/build caches and rejects secrets, symlinks, nested generated directories and oversized traversals. Paths are sorted POSIX-relative strings and each entry stores a content SHA-256; the tree hash is SHA-256 of RFC 8785 canonical JSON of the sorted entries. No absolute paths or mtimes affect identity. The controller must freeze an immutable clean evaluation copy; hashing a mutable directory alone does not freeze it.

`freeze.ts` emits source, evaluator dependencies, suite and required-policy commitments. It neither imports task code nor runs a command. Its `executionStatus=NOT_RUN` and `evidenceOrigin=none` are intentional. The evaluator manifest includes the experiment controller/isolation code, guest/worker bridge, separate toolchain lock, shared contract/report/verdict/loader code and parent dependency lock so changes to those dependencies change the evaluator identity.

`receipt.ts` assembles a strict receipt and its canonical digests from supplied check records. Assembly alone supplies no authority. Only the trusted controller may bind actually observed check-artifact bytes, publish them outside agent custody and add their exact bundle digest/freshness pins to the protected store's allowlist.

The hosted app has no evaluator, runner, receipt-upload or allowlist-registration endpoint. Do not add one to make this preparation appear live. See the parent `docs/BOOKING-EVALUATION.md` for remaining integration gates.

`future.ts` adds public-safe future task/oracle descriptors, data-only exact-candidate requests and a synthetic receipt wrapper over the same assembler/store. It contains no private behavioral assertions or candidate execution. The future policy preserves the baseline checks and adds three separately identified team checks; the installed guest still needs independent source installation/admission; the source bridge now supports them. [Future custody, staged commitments and blocked provisioning](../../../docs/BOOKING-FUTURE-EVALUATION.md).

The disabled-by-default integration is documented in [the operator runbook](../../../docs/BOOKING-RUNNER.md). `guest.ts` runs in the protected offline microVM; `oracle-driver.ts` observes check process exits there. `remote-oracles.ts` keeps assertions outside the candidate's resource-limited worker; `worker.mjs`/`client.mjs` carry only behavior RPC, with no oracle or publication authority. The toolchain recipe has not been installed or executed in a sandbox by this slice. The existing private infrastructure grader is not automatically replaced.

The [restricted team bridge](../../../docs/BOOKING-TEAM-BRIDGE.md) now supports a strictly pinned eight-check future profile in source. `grade-profile.ts` is shared standalone host/guest validation; `team-rpc.mjs` contains only public bounded behavior transport/seed; `team-installation.ts` admits only the fixed root-owned private package. The guest copies no assertions/profile/receipt code into its worker. Unknown operations, stale source/lock/task/evaluator/policy and missing private installation fail closed. Baseline profile and resource ceilings remain unchanged. Private suite provisioning and protected behavioral execution remain BLOCKED/NOT_RUN; no changed runtime was installed or admitted. Existing real-agent smoke/offline adapters cannot select this future profile.
